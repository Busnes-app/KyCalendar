# Web

## Purpose
React 19 + TypeScript + Vite PWA frontend using the ky-ui suite theme catalog (six light/dark pairs, Busnes the default), client-side WebCrypto PoW CAPTCHA, the Phones and apps (app password) page, the group calendars admin screen, and administrative management panels.

## Ownership
Owns user interface components, service worker caching, PWA installation manifests, and frontend theme switching.

## Local Contracts
- Web themes default to the Busnes.app cream/light and charcoal/dark palettes with orange accents, following the OS until a browser-local choice is saved. Preserve existing named themes and saved choices.
- A signed-in user with `must_change_password` sees only password replacement and sign-out. Replacement uses `secureFetch`, returns to login after session revocation, and never exposes the normal navigation before completion.
- The product name is `KyCalendar`: the brand, title and manifest use it, and `app_name` (`KY_APP_NAME`, default `config.DefaultAppName`) falls back to it.
- `src/styles/theme.css` holds fonts, named palettes, the app shell, buttons, fields and badges; it resets every margin, so it restores `dialog { margin: auto }` for modal centring. Its spacing, radius, field-border and modal-shadow variables alias the ky-ui geometry tokens (8px rhythm); body text is 15px. Button hierarchy: a bare `button` is primary (its accent hover excludes `.ky-nav-item` and the shell's quiet controls (`.ky-user-signout`, `.ky-license-link`, `.ky-about-close`, `.ky-auth-link`, `.ky-menu-trigger`, `.ky-menu-item`) through `:where()`, keeping its specificity: navigation rows take ky-ui's neutral hover, which sits below this rule since ky-ui 0.3.0; `browser/nav.spec.mjs`); `.btn-secondary`, `.btn-ghost` and `.btn-danger` (every destructive action) step down, and all but ghost share the primary's disabled look; `.btn-sm` is the row style, with smaller text but the same 40px height as every button, input and select. Inputs keep a 3:1 `--field-border`; `:focus-visible` draws a 2px accent ring at a 2px offset, on the border itself (offset -1px) for text fields, selects and textareas so it reads as one ring; `prefers-reduced-motion` stops transitions and animations.
- `src/styles/ui.css` is the shared page layer, following KyIdentity's house style on ky-ui tokens: `.page` (left-aligned beside the navigation, 2rem in, content up to 72rem), `PageHeader` (ky-ui `ky-page-head`; a primary create action is `.ky-page-action` with a leading Plus and opens a `Modal`), `MoreMenu` (`components/MoreMenu.tsx`: a ⋯ or + trigger and a native popover `role=menu` of `.ky-menu-item`s, always visible, so touch screens reach it), `.card`, `.form`/`.field`/`.inline-form` (constrained widths), `.table-card` + `.data-table` (right-aligned `.row-actions`; `.stacked` turns rows into labelled blocks at 720px or less, so tables never scroll the page), `.record-list`, `EmptyState`, `p[role=alert|status|note]` messages, `Modal` (`dialog.modal`: title, description, body, `.modal-actions` with the primary action last and destructive ones `push-start`) and `CodeBlock` (scrolls inside its own box, with Copy). Pages compose these from `src/components/ui.tsx` rather than inline styles. Calendar forms use `.kc-form`, `.kc-check` and `.kc-actions` from `src/styles/calendar.css`.
- `src/calendarColors.ts` keeps calendars apart: a new personal calendar (sidebar) or subscription takes the first `PALETTE` colour none of the user's calendars shows, a new group calendar (admin) the first unused by group calendars from a later start, and of the calendars stored without a colour the first (the default calendar) shows the theme accent (`ACCENT`, `var(--accent)`) and any further one the next unused palette colour (`calendarColors`), consistently in the sidebar and on events. Event text is charcoal or white by contrast (`textOn`), or `--button-text` on the accent. No server default is involved.
- Strict TypeScript type safety without unused imports.
- The authenticated shell uses a persistent 240px sidebar (`--ky-sidebar-size`) with 40px, 14px navigation rows; the selected page is marked by a quiet surface and slim accent rail. The account region at its foot is ky-ui's `ky-user` block (name over role, the username when the display name equals the role, so never the same word twice; a labelled `ky-user-signout` with lucide `LogOut`). The brand mark (`.brand-mark`, sidebar and sign-in) is inverted when `data-scheme` is `dark`. At 720px or less, brand and account share the top row (Sign out keeps its accessible name, label hidden), the licence line moves to the end of the page (`.app-page-footer`, a second `LicenseFooter` shown only there), and the navigation scrolls horizontally beneath, fading out before a rule that separates it from the Calendars disclosure, in the same order, with the sidebar slot's content (the calendar list disclosure) at the end of that row. `AppHeader`'s `useScrollCue` marks which ends of a scroll box hide content (`data-cue`); the CSS fades those edges of the phone navigation and of the wide sidebar slot, so clipped items read as "more to scroll". Focused navigation rows scroll fully into view; the phone nav fade is removed while focus is inside the strip.
- Themes: `src/theme.ts` adapts ky-ui `themes.js` and lists each pair's three choices (`THEME_CHOICES`). The saved `ky_theme` value is `system` (Busnes following the OS), a pair ID such as `ocean-pair` (that pair following the OS) or a half ID (a fixed mode). Aliases resolve to their half (`patina` is Patina Ky, `Paper Clean` is Nord Light); IDs ky-ui removed fall back to `system`. Choosing sets `data-theme` to the resolved half and `data-scheme` to its light or dark and `applyThemeVariables` sets a named palette inline (cleared for Busnes and system); every OS scheme change re-applies, so a saved pair re-resolves.
- `src/pages/Appearance.tsx` (tab `appearance`, both roles) is the theme page: `h1`, the immediate/browser-local sentence, then six pair cards (`role="group"` named by an `h2`), each with ky-ui's two-half preview and a Match system / Light / Dark segmented control. All eighteen choices are one native radio group; the checked segment is filled, bold and carries a check icon, and its card takes an accent border. No inline styles. The shell carries no theme select (owner decision 2026-10-26); only the sign-in page keeps one (`ThemeSwitcher`, the same eighteen choices grouped by pair, a field-styled `select.theme-selector` with a padded chevron drawn from gradients), and admin Settings has none.
- State-changing requests use `secureFetch` so the `ky_csrf` cookie is mirrored into `X-CSRF-Token`; the server binds it to the session, or before sign-in to the pre-session cookie. `Login.tsx` calls `ensureCSRF()` (GET `/api/auth/me` when no `ky_csrf` cookie exists) before its login and MFA posts. Its CAPTCHA callback is stable across typing and token updates; a failed attempt still remounts the single-use challenge.
- `src/pages/TwoFactor.tsx` (tab `security`, labelled "Two-step verification", offered and rendered only when `sso_provider === 'local'`, for both roles): off, it takes the password and starts enrolment, then shows the setup key with Copy and an `otpauth://` setup link (no QR library is bundled) and confirms the first code; the ten recovery codes show once in a `role="status"` card. On, it turns off with the password and a code. Failures show the server's message as `role="alert"`; `onChange` updates `user.totp_enabled`.
- Register the service worker from the production JS bundle; keep `script-src 'self'` intact. There is no device-pairing UI (R27); native CalDAV clients use app passwords from Phones and apps.
- `src/pages/AppPasswords.tsx` shows a new password once, and a `role="alert"` message when listing, creating, revoking or changing access fails (non-OK or network error; `reauth_required` asks for a fresh sign-in). It always sends a scope: "Calendar app (CalDAV)" is `dav`; "AI agent" offers three radios with one hint line each, in order "Read only" (`mcp:read`, the default), "Edit its own events" (`mcp:write-own`) and "Edit any event" (`mcp:write-any`); a write level shows the same warning the list's confirm uses. Agent rows name their access with the same three names (`ACCESS`). A new agent token shows with OpenClaw and Hermes Agent config that reads it from `KYCAL_TOKEN` (never the token itself in a snippet) and the skill install commands. Agent rows have an access selector (`PATCH`; widening asks to confirm with the create form's warnings, narrowing does not) and "Revoked if unused by" from `revoke_after`.
- `src/pages/GroupCalendars.tsx` is admin-only (tab `group-calendars`): create a group calendar ("New group calendar" opens a dialog), add a group with a role, change or remove a grant, delete a calendar after a confirm. A 403 `reauth_required` asks for a fresh sign-in. Every failure shows a `role="alert"` message, and nothing on it shows events. Empty calendars use plain access guidance; the Group selector is disabled when no unassigned groups exist and distinguishes no groups from all groups already granted access. Add group stays disabled until an available group is selected; phone grant fields fill the card width.
- `src/admin.tsx` holds the admin screens' fetch helpers (`send` resolves to null on a network error, `failure` reads `{error, code, count}`), the step-up message and `SourceBadge` ("Managed by ..." for any source but `local`).
- People and Groups page through the server's 200-row pages (`pageURL`, `LoadMore`): while the list's `total` exceeds the rows shown they show "Showing N of TOTAL" and a Load more button that fetches the next `offset` and appends. Load more is disabled while a request is in flight, and only the latest request lands, so a double click appends once and a search or reload replaces a Load more still pending. A People search, and the reload after any change, start again from the first page, whose URL carries no `offset`.
- `src/pages/People.tsx` is admin-only (tab `people`): a one-line lede; columns Person (display name, with the username only when it differs), Role, Email (only when someone has one), Status and Last sign-in; search, add a person (the server-generated temporary password shows once in a dialog with Copy and an out-of-band hand-over note), and, on local rows only, Edit plus a ⋯ menu holding reset password, make administrator or everyday user, and disable or enable, each destructive one behind a confirm. Your own row offers no demote or disable. Synced rows show their badge and no actions, except "Reattach" (named "Reattach <user> to current sign-in") where the list marks `needs_reattach`: its confirm names the row's `bound_to` and the list's `signin_binding` and asks the admin to be sure it is the same person; the POST sends that `signin_binding` as `{binding}`, and a 409 `binding_changed` shows the server's message and reloads the list. A 403 `reauth_required` asks for a fresh sign-in; `last_admin` and `self` show the server's message.
- `src/pages/SignIn.tsx` is admin-only (tab `signin`): a one-line lede; the Provider field's hint carries the role rule, that switching provider or issuer disables the previous provider's accounts, and that People can reattach one; provider (none, Single Sign On (KyIdentity), another OIDC provider; the KyIdentity provider and its default button label read "Single Sign On" in the UI), button label, issuer, client ID and secret, with the callback URL and a Copy button. A field whose source is `environment` is disabled and names its variable; the secret is never rendered, only a placeholder ("Stored; leave blank to keep it" or "Required"), and a blank one keeps the stored secret only while provider, issuer (exact, surrounding spaces aside) and client ID are unchanged (otherwise the server's 400 shows). Test runs discovery without saving; Save asks for confirmation stating the server's account count when a provider change disables accounts, then resends with `confirm_disable`; a 403 `reauth_required` asks for a fresh sign-in.
- `src/pages/Groups.tsx` is admin-only (tab `groups`): create ("New group" opens a dialog), rename and delete local groups, and add or remove members found by search (only active everyday people are offered; the search box clears after an Add). Rename opens an inline form from the group's header. SCIM groups show their badge and their members read-only. The delete confirm names how many group calendars lose the group's access; a 403 `reauth_required` asks for a fresh sign-in; a `scim_conflict` group shows an alert to rename it.
- `src/pages/SCIMAdmin.tsx` is admin-only (tab `scim`) and reads only `GET /api/admin/scim`: enabled or disabled, whether a bearer token is set (never its value; when none, how to set `KY_SCIM_TOKEN`), the SCIM base URL and the first page of provisioned accounts. It never calls `/scim/v2` (a session cannot). A failed load is a `role="alert"` message.
- `App.tsx` renders the admin pages (`dashboard`, `people`, `groups`, `group-calendars`, `signin`, `scim`, `backup`, `settings`) only for `role === 'admin'`, and `calendar` and `devices` only for everyday users, `security` for any local account and `appearance` for everyone; `AppHeader` offers the same split.
- `src/calendarApi.ts` is the only client of the calendar and event routes. It sends a strong `If-Match` on event writes and throws `ApiError{status, code}`. `src/eventForm.ts` is the pure form↔body translation: series times for 'all' edits, inclusive all-day end dates in the form and exclusive on the wire, instants from browser-local values. `src/linkify.tsx` is the only way event text becomes markup: plain text plus http/https links with `rel="noopener noreferrer"`. FullCalendar is pinned to 6.1.21 for every package.
- `src/pages/CalendarPage.tsx` is the landing page for everyday users (tab `calendar`) and is never shown to admins. `App.tsx` lazy-loads it as a same-origin chunk (FullCalendar stays out of the main bundle) and derives the landing tab from the role, so no other page renders first. Views are month, week, day and list, with week list as the initial view at 720 px or less. Day and week views fill the window below the heading (56px an hour) and scroll inside it over the full day, opening at 07:00 (`scrollTime`, reapplied when switched to from month or list); month and list take their natural height. Events come from `GET /api/events` in the browser's zone, for visible calendars only; visibility is stored in `localStorage` key `kycalendar.hiddenCalendars`. `src/styles/calendar.css` themes FullCalendar from the product aliases (`--bg`, `--ink`, `--accent`…), never `--ky-*` colours directly, so the saved named palettes apply to the calendar too. Its chrome is neutral: New event is the one filled accent control, the selected view is an accent tint plus an accent rail, Today keeps the arrows' outline even while disabled, and today is a neutral column with an accent header. Time-grid headers show the weekday over the date; event times are compact ranges ("9 – 9:15"; the axis carries am/pm), and events shorter than 30px show the title then the range on one line, at the usual label sizes (a range that does not fit wraps to a clipped row, so it drops before the title shortens), at least 20px tall. The hour grid scrolls under FullCalendar's fixed day headings and all-day strip; `useScrollCue` marks its scroller and the CSS fades the edge with more hours. Month days from other months are muted by colour only (FullCalendar's own opacity is reset; ≥ 4.5:1, `browser/month.spec.mjs`), and month titles end in an ellipsis. At 720px or less Month shows start times for timed entries, following the owner’s2026-10-28 preference for the fresh baseline over abbreviated titles. Timed titles stay in the accessible name and event form; all-day bars keep single-line labels. The owner rejected round3 forced word wrapping and the subsequent three-letter title treatment. Week keeps readable day columns in an internally scrolling, keyboard-focusable `Week calendar` region with a scroll hint; it opens at the start of the week with its time axis visible, using native horizontal scrolling. Date/view updates reapply the Week region name/tab stop and clear them for Day because FullCalendar reuses the time-grid DOM. Toolbar and page stay within the viewport; the phone timezone note spans the heading width. Time-grid titles use one ellipsized line in short blocks and up to two lines when the block is at least 60px tall. Grid events get `role="button"` (`eventDidMount`) so time and title are their accessible name, and they open the same form. While events load, the heading says "Loading events…" (`role="status"`) and an empty list says so; after a failed load the list says "Events could not be loaded." beside the alert, never "No events to display". There is one left column, never two adjacent left panels (user preference, 2026-10-26): `CalendarSidebar` always renders through a portal into the app sidebar's `.app-sidebar-slot` (below the navigation, scrolling between it and the account region), so the canvas takes the full content width. The portal target never changes with the width, so crossing 720px never remounts the list or drops a half-filled add, rename, subscribe or change-link form. It sits in a native `<details>` (`.kc-picker`): above 720px it is forced open with its summary hidden; at 720px or less the summary is a "Calendars" disclosure in the header's navigation row, closed at first (List stays the narrow default view), whose panel drops over the page and scrolls inside itself. Escape inside it closes it and returns focus to the summary; focusing anything in the list keeps it open, so a form in use stays visible when the screen narrows. On pointer screens its row tools appear on hover or keyboard focus. Opening the rename or change-link form moves focus into it (its trigger disappears), and the subscribe/change-link form scrolls into view from its heading. The section header has one "+" (`MoreMenu`, "Add a calendar") whose menu offers New calendar and Subscribe to a calendar; each opens a `Modal` rendered on the body (the list may sit in a closed phone disclosure) whose draft survives the breakpoint, and closing returns focus to the +. Escape inside a dialog or menu never closes the phone disclosure. The sidebar adds, renames, recolours and deletes calendars only where the role allows; edit and delete are icon buttons named "Edit <name>" and "Delete <name>". The add form and the admin group-calendar form choose what a calendar holds (`HOLDS`: Events, Tasks, or Events and tasks, sent as `components`); a calendar without VEVENT shows "Tasks · open in a tasks app". There is no task view.
- ICS subscriptions live in `CalendarSidebar`: "Subscribe to a calendar" posts link (https or webcal), name and colour; a subscribed calendar (`subscription` set; its link is never returned) keeps its subscription details in the edit panel the pencil opens (closing the panel also closes an open Change link form): "Subscribed · host", "Updated <relative>" or "Not yet updated", its fetch `error` as `role="alert"` (shown under the calendar name while the panel is closed), Refresh (a 429 says to wait) and Change link (`PATCH`, one Link field). Form failures show the server's message in the form. `canAddEvents` keeps readers, subscriptions and calendars without VEVENT in `components` out of new-event targets; their events arrive `editable: false`, so they are read-only with no extra logic.
- `src/components/EventDialog.tsx` creates, edits and deletes events, with the scope choice (this or all) for recurring events and "all" times loaded from the series. Custom rules show "Custom (edit on your device)" and are kept. "All events" on a recurring event shows the `ScopeDialog` warning that moving all events drops single-event changes, and its delete confirm says every occurrence. A 412 asks the user to close and reopen; every close refetches events, so reopening carries the current etag. After the replacement event nodes render, focus returns to the same logical event, or New event if it was deleted. Read-only events render as text through `linkify`, with no actions. Escape closes it.
- Invitations show only when `/api/settings` carries `scheduling: true` (`App.tsx` passes it and the user's email through `CalendarPage`). The organizer, or anyone on an event with no organizer, gets a People section in the event form: invited emails with their answer in words (Accepted, Maybe, Declined, Awaiting reply), Remove, and an Invite field (Enter adds; never the user themselves). Save sends `attendees` only when the list changed (`[]` removes everyone). An invitee (`my_status`) sees "Organized by", the answers read-only and Accept / Maybe / Decline (`aria-pressed` on the current answer), which call `rsvp` with `If-Match` (the occurrence only when "This event" is chosen) and close like a save.
- Dragging or resizing an event saves through `updateEvent` (with `If-Match`). A recurring occurrence first asks `ScopeDialog` (a modal `<dialog>`): This event, All events or Cancel; "All events" shifts the series start and end by the drag's calendar delta on wall-clock times (DST-safe) and sends `repeat.freq = "custom"` to keep the stored rule. When the series start changes date where the server reads it (the TZID; with no TZID, UTC and local must agree, since the series may be UTC or floating; the local date for all-day; a TZID `Intl` cannot resolve refuses any start move), weekly weekdays rotate by the weekday shift (sent as the weekly preset), a rule derived from DTSTART (daily, monthly, yearly, weekly without weekdays) follows the start, and a custom rule is refused (use the event form); the server drops one-off changes (overrides, deleted occurrences) when the series start moves, and the dialog says so. Toggling all-day on a repeating event with "All events" is refused (use the event form). Cancel, Escape or a failed save reverts the drag; a 412 also reloads with a conflict message. Readers and partial events are not draggable (`editable` false).
- `public/fonts/` ships only the faces `src/styles/theme.css` loads (Space Grotesk variable; IBM Plex Mono Regular, Medium, SemiBold) with each family's `OFL.txt`; add a file there only together with the `@font-face` that uses it. `tsconfig.tsbuildinfo` is build output and ignored.
- CSP is `font-src 'self' data:` because FullCalendar injects its icon font as a data URI; no other data or remote source is allowed.
- Worker caching is limited to the same-origin public shell, manifest and assets. HTML is network-first with offline fallback so deployments refresh; dynamic/auth routes stay uncached.
- `Login.tsx` and `ChangePassword.tsx` render ky-ui's `ky-auth` sign-in markup (`.ky-auth-field`, `.ky-auth-check` from `CaptchaWidget` with `data-ky-state`, `.ky-auth-submit` with lucide `LogIn`, `.ky-auth-link`); no local auth CSS remains. `Login.tsx` shows "Continue with <label>" under a `.ky-auth-divider` only when `/api/settings` carries `signin_name` (a live provider with SSO enabled); there is no SSO button otherwise.
- `Backup.tsx` shows the schedule's real state: "Manual only", "Waiting for recovery key" or "Waiting for a destination" while no run is possible, and only then "Next <time>"; the "Back up automatically" select is capped at 40rem. It shows `last_run` under the schedule, as an alert when it failed, so a failing scheduled backup is visible on screen.
- `Settings.tsx` shows the server's version from `/api/settings` (`version`, signed-in only) under About.
- `LicenseFooter` (in `AppHeader`, below the account region) is ky-ui's `ky-license-link` `© <year> · MIT License`; it opens the `ky-about` dialog: KyCalendar, a `v<version>` badge from `/api/settings` `version` (none without it), "Developed by Busnes.app" and `src/mit.txt`. `src/mit.txt` is `LICENSE.txt` byte for byte (`license_test.go`); on phones it closes the page instead of the sidebar.
- `Backup.tsx` warns for as long as `database_driver` from `/api/backup/status` is not `sqlite`: only the SQLite path can snapshot a database into a capsule, so a Postgres deployment makes no capsules at all.

- Sign-in responses are validated at the HTTP boundary. A `managed` response disables configuration, Test and Save, explains KyQuickStart ownership and leaves callback Copy available. Source `installer` is distinct from environment and saved settings.

## Verification
- The calendar list is one mounted `CalendarSidebar` in the app sidebar slot at every width: in the sidebar after the navigation above 720px, behind the header's Calendars disclosure at 720px or less. Keep every calendar control available in both presentations, and keep drafts across the breakpoint (`CalendarPage.test.tsx`, `browser/resize.spec.mjs`).
- Browser setup: build the frontend, run `go build -o .browser/server ./cmd/server` at the repo root, then `cd web && npx playwright install chromium && npm run test:browser`. CI also installs browser OS dependencies.
- `make test-web` or `cd web && npm ci && npm test`, then `npm run build` (vitest with jsdom; `src/pages/Backup.test.tsx` renders the recovery screen against a stubbed status route). Commit `web/dist` after a build; CI diffs it.

## Shared browser UI

- `src/ky-ui/` is generated from Busnes-app/ky-ui, pinned by `VERSION` file hashes. Change shared colors, navigation states and storage helpers upstream, then run its consumer sync with an explicit worktree map; do not hand-edit vendored files.
- Products own layout, routes, saved choice keys and named palettes. Busnes aliases consume shared tokens; mark primary navigation with `ky-nav-item` while preserving current-page semantics.
- Verify vendored files with `node src/ky-ui/check-vendor.mjs` from this document's directory. Builds/CI run that check. Rendered evidence and capture limitations are recorded in the repository-root `UI-VERIFICATION.md`.
