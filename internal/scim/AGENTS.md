# SCIM

## Purpose
Adapts the `elimity-com/scim` RFC 7643/7644 server to the local user and group stores for enterprise provisioning from Okta, Azure AD / Microsoft Entra ID, OneLogin, and KySignOn.

## Ownership
Owns local persistence adapters and bearer authentication; the library owns `/scim/v2/Users`, `/scim/v2/Groups`, discovery endpoints, schema validation, filter/PATCH parsing, pagination, and SCIM error serialization.

## Local Contracts
- `POST /Users` with an `externalId` that names an existing `kysignon` user whose `sso_issuer` equals the stored binding adopts that row; one of another binding (or unstamped) is never adopted: 409 `uniqueness`. Adoption keeps the row (same ID, provider kept) and goes through the Replace path, with its revocation, and audits `scim.user.adopt`. This join assumes the SCIM source is KyIdentity, whose `externalId` is its user ID and the KySignOn `sub`; do not feed SCIM from another IdP while KySignOn is enabled, or unrelated accounts with colliding IDs would be joined.
- A created user is stamped with the stored sign-in binding (`sso.Bound`, "" when none); replace, patch and adoption never change `sso_issuer`, so re-activating a row the binding moved away from does not let the new provider sign in as it.
- Groups have an owner (`groups.source`). SCIM creates `scim` groups and lists, reads, replaces, patches and deletes only those; a local group is 404 to SCIM, so a reconciling IdP never sees, renames, empties or deletes one. A create whose name a local group holds in any case is a 409 and sets setting `ConflictKey(name)`, which the Groups screen flags until the local group is renamed or deleted.
- Local accounts (`sso_provider = 'local'`) are not SCIM's, as with local groups: the user list and its filters omit them and their count (`UserFilter.SSOOnly`); GET, PUT, PATCH and DELETE on one are 404 with no write; a create whose `userName` a local account holds in any case is 409 `uniqueness`. Group members a create, PUT or PATCH names must be existing non-local accounts (`UserStore.SSOUserIDs`), else the whole request is 400 `invalidValue` before any write (an unknown and a local ID answer alike). A local membership a SCIM group already holds is neither reported nor removed by SCIM; the admin Groups screen still shows it.
- Group `PATCH` follows RFC 7644 3.5.2 on `members` (`groupPatch`): `add` appends (duplicates ignored), `remove` with path `members[value eq "<id>"]` drops that member (absent is a no-op), `remove` of `members` drops every SCIM-visible member, `replace` replaces them; a path or value object without a path may also replace `displayName` and `externalId` (other attributes are ignored). Any other member filter, or a member filter on add or replace, is 400 `invalidFilter`; a member sub-attribute path is 400 `invalidPath`. Every member any operation names is checked (`scimMembers`) before anything is written, and only the membership difference is written. KyIdentity sends no group PATCH (it PUTs the whole membership); `TestSCIMGroupPatchMemberOperations` pins the semantics.
- A refused write is logged and audited (`refusedUser`, `refusedGroup`) with the target ID (resource, "" when none) and `reason=<code>` only, never the request or token: `scim.user.refused` for a create refused adoption (`other_binding`, resource the existing row), a create over a taken name (`name_taken`) and a 412 (`access_changed`); `scim.group.refused` for a create over a taken name (`name_taken`, resource the group holding it) and a refused member (`invalid_member`, on create, PUT and PATCH). `TestSCIMRefusalsAreAudited` pins it.
- Content-Type for all SCIM endpoints must be `application/scim+json`.
- Requests must be authenticated with the configured bearer token.
- User de-provisioning via `PATCH` with `active: false` updates user status to `inactive`. Replace, patch and adoption store through `UpdateSCIMUser` (`save`): username, email, display name, role and status of a non-local row only, and, when role or status changed from the stored row, every grant revoked with the access write, row first. A failure never leaves access the IdP removed and never grants access that was not written: SCIM writes only the access it changes; a removal always lands; a grant lands only if nothing changed the account since SCIM read it, otherwise SCIM is asked to retry. Replace and Patch pass the role and status they read (`expectedRole`, `expectedStatus`) with the requested ones. A removal (deactivation, demotion) commits with the revocation first, so a failing profile write (a `userName` another row holds: 409 `uniqueness`) still returns the error but the person is already out. A grant (activation, promotion) commits only together with the profile write and only if the stored role and status both still equal what was read (as this request's removal left them); otherwise nothing more is written and the IdP gets 412 (RFC 7644 3.14, the resource changed; retry from a fresh read). A role or status the request leaves unchanged is never written, so a profile-only PATCH never undoes a concurrent webhook deactivation or login demotion. Replace and Patch answer with the account re-read after the write, never the request merged into the read. `TestSCIMProfilePatchNeverRestoresAccess`, `TestSCIMGrantOnAChangedAccountAsksForARetry` and `TestSCIMGrantNeedsRoleAndStatusUnchanged` pin it. `TestSCIMAccessChangeWithAFailingProfileWrite` pins both.
- No roles means no admin grant: PUT without roles or with an empty list, PATCH `remove` on `roles` (matched by attribute name, so URN-prefixed and value-filtered paths count) and PATCH replace with an empty value all set role `user` (and so revoke grants). Other PATCH `remove` operations are ignored.
- Only the value `kycalendar.admin` in `roles` makes an admin (`access.IsAdmin`); any other value is an everyday user. Admins are emitted with `roles: [{value: kycalendar.admin}]`.
- Users filters: one `eq` on `userName`, `email`/`emails`/`emails.value` or `displayName`, matched case-insensitively on that attribute alone, or `externalId eq`, KyIdentity's lookup of the account it provisions: exact and case-sensitive on `sso_subject`, only `kysignon` and `scim` rows (`sso.AccountProviders(kyidentity)`) bound to the stored binding (`sso.Bound`), the same rows create would adopt, so a lookup never returns a local row, an OIDC subject or another binding's account. Groups filter: only `externalId eq`, exact, SCIM groups only (`GroupsByExternalID`). Anything else is `invalidFilter`. The quoted value (`parseEqFilter`) takes the escapes `\"` and `\\` (as KyIdentity sends them); any other escape, an unterminated quote and a value over 1024 bytes (`maxFilterValue`, after unescaping) are `invalidFilter`. `TestSCIMFilterValueEscapes` pins it. KyIdentity-server `internal/sync` (`findSCIMResource`) depends on both lookups; its other calls (user POST, GET by id, PUT, PATCH `replace active false`; group POST, GET by id, PUT, DELETE with KyCalendar user IDs as members; unfiltered paged listing) use what is described here.
- SCIM protocol models and parsing must come from `github.com/elimity-com/scim`; do not add parallel local request/response implementations.
