# API

## Purpose
Exposes HTTP REST routes, authentication endpoints, Single Sign-On callbacks, SCIM endpoints, backup restore drill handlers, and static React PWA hosting.

## Ownership
Owns HTTP routing, request parsing, session cookie validation, CORS headers, and error response formatting.

## Local Contracts
- POST `/api/auth/change-password` accepts any local session (a restricted one with `must_change_password`, or a user changing their own password from Account settings), the current password and a different policy-valid new password; an SSO account gets 409. Browser CSRF and per-IP/account limits apply. Success revokes all sessions and requires sign-in again; flagged sessions get `password_change_required` on protected routes and public-only settings.
- All JSON API endpoints return structured errors `{"error": "message"}` upon failure.
- Non-API routes fall back to serving `web.Handler()` for client-side SPA routing.
- Every route is registered through `s.handle`, which records its pattern. `authz_matrix_test.go` holds one row per pattern (public, session, everyday, admin-only, grant-manager, SCIM) and one row per CalDAV operation, each run against anonymous, owner, reader, editor, manager, non-member, admin and deactivated callers. `TestEveryRouteIsInTheMatrix` fails on a route without a row, so adding a route means adding its row. An `allow` cell fails on 401, 403, 404 and any 5xx.
- Backup routes and theme writes are admin-only: capsules and settings carry site data and secrets. Step-up actions call `requireStepUp(w, r, what)` (`stepup.go`): the session's credentials must be younger than 10 minutes (`stepUpWindow`, from `Session.CreatedAt`), else 403 `reauth_required` with `Sign in again to <what>`. An SSO session is dated from the ID token's `auth_time`, so a silent sign-in on a live provider session is not fresh; with no `auth_time` it is dated from `iat` (for the logout fences) and stored `unproven` (`sessions.unproven`, migration 22), which never passes a step-up. `GET /api/sso/kysignon/login?step_up=1` (the web's SSO link after signing out) sends `max_age=0` and `prompt=login`; its callback answers 401 unless `auth_time` is present and no older than the request (one minute's leeway). The request's start rides in the `ky_nonce_<state>` cookie (`<provider ID>.<nonce>[.<start>].<mac>`) under an HMAC over the state and value with a per-process key, so the browser cannot back-date it; a cookie that fails the MAC answers 400, and a signed start older than the cookie's five minutes answers 401. KyIdentity must honour `max_age`. The route tables mark every step-up route. Step-up runs before the body is read. `TestIrreversibleBackupActionsNeedRecentSignIn` pins it for pair, pin and export; other backup routes rely on admin-only plus `TestPrivilegedEndpointsRequireAdmin`. Routes are registered with method patterns, and because the SPA catch-all answers any method, tests pin that a wrong method never reaches a backup handler rather than expecting 405.

**Multi-tenant admin surface** (`admin_tenancy.go`, tenancy spec "Admin surface", build step 5). Single-tenant answers are unchanged.
- **`404` (plain, the same for every caller), via `singleTenantOnly`:**
  - business features (D9): `/api/admin/groups*`, `/api/admin/calendars*`, `/api/admin/resources*`, `/api/resources*` and `/scim/v2`;
  - account writes (D8): `POST`/`PATCH /api/admin/users…`, `role`, `disable`, `enable`, `reset-password` and `reattach`.

  The gate runs before sign-in, so the answer never depends on who asks.
- **`PUT /api/admin/signin` and `POST /api/admin/signin/test`** answer `403 sign_in_fixed` (D2).
- **`GET /api/admin/users`** needs `?org=<id>` (`400 org_required`, `400 bad_org`). It lists that org's accounts and adds `bytes`, each listed account's stored calendar bytes.
- **`GET /api/admin/audit`** lists platform rows (`org_id` NULL) by default, or with `?org=<id>` that org's rows.
- **Every `?org=` read** first writes a `staff.read` platform row (`LogPlatformAudit`: staff user, `org=… route=…`), which outlives the org's purge. A failed write answers 503 and reads nothing.
- **`GET /api/admin/scim`** shows `enabled:false`.
- **New `GET /api/admin/orgs`** (multi-tenant only; 404 in single-tenant): the org mirror (`ListMirroredOrgs`: status, revision, enabled, quotas, `seen_at`, stored bytes).
- **Tests:** `TestMultiTenantAdminSurface` and `TestSingleTenantAdminSurfaceUnchanged`.

- `cleanName` is the rule for every admin-entered display name (group create and rename, People display names, the sign-in button label): trimmed, 1-255 bytes, and no control (Cc), format (Cf: zero-width, bidi overrides, soft hyphen, BOM) or line/paragraph separator (Zl, Zp) characters, else 400 naming bytes. A name equal to the stored one (People display name, group rename, saved sign-in label) is not revalidated, so a name stored under an older rule never blocks an unrelated edit. `TestAdminNamesRefuseInvisibleCharacters` and `TestStoredInvisibleNamesDoNotBlockOtherEdits` pin it.

- Event writes decode the stored object, apply `calendar.NewEvent`/`EditAll`/`EditOne`/`DeleteOne`, encode, and store through `davbackend.Write` with the request's `If-Match` (exactly one strong ETag `"<etag>"`, non-empty, no `"`, `,` or whitespace, not `*`; absent is 428, anything else malformed -- empty, `*`, `W/`, a list, unquoted -- is 400, because the store reads `""` and `*` as no precondition), so web edits get CalDAV's validation, ETag check, quotas and change log. Authorization (404/403) and `If-Match` (428/400) come before body validation. `davbackend.Write` refuses objects over `calendar.MaxObjectSize` (`ErrTooLarge`: 413 `too_large` here, CalDAV `max-resource-size` there). Titles, locations and descriptions refuse control characters other than newline and tab; years outside 1900-9000 are 400. `If-Match` rows: 428 no header, 400 malformed.

- The completion log (`task_completions`) is written in `davbackend.WriteMeeting` for every VTODO write, web, MCP and CalDAV alike (`tasks.Change`): a task newly COMPLETED, or a repeating task moved to the rule's next occurrence, logs one row per writer, task and occurrence; reopening deletes it; a COMPLETED time in the future or before CREATED becomes the receive time.
- Task writes (`tasks.go`) share the event write path (`saveEvent` → `davbackend.WriteMeeting`) and edit the stored VTODO in place through `internal/tasks`. `taskBody.patch` is the boundary: title 1-1000 bytes, notes ≤ 64 KiB, ≤ 20 tags of ≤ 64 bytes without commas, priority 0-9, dates `YYYY-MM-DD` or RFC 3339 (years 1900-9000), lengths 0-1440 minutes, RRULE ≤ 200 bytes parsed by `rrule-go` and daily to yearly, ≤ 10 reminders, files as `eventFiles`, body ≤ 256 KiB; control characters refused. `checkParent` keeps a parent in the same list, refuses cycles and more than 3 levels. Task text, tags and queries are never logged or audited; MCP task writes audit IDs only.

- Event instances carry `calendar_id, uid, recurrence_id, etag, title, location, description, start, end, series_start, series_end, all_day, recurring, override, repeat{freq,weekdays}, floating, unknown_zone, partial, zone, editable`. Timed `start`/`end` are RFC 3339 in the viewer's `tz`; all-day ones are dates. `series_start`/`series_end` are the series' first occurrence, same format as start/end; the web edits all occurrences from these. - The write-once, irreversible backup handlers (`handlePairRemoteRecovery`, `handlePinKey`, `handleRunBackup`, `handleDeleteGroupCalendar`, `handleDeleteCalendar`, `handleDeleteGroup`) write on `context.WithoutCancel(r.Context())` so a dropped connection cannot leave a pin, a pairing or a deposit half-written with no audit row; the deposit's snapshot and upload and the pairing claim run on `stopping`, which only `StopDetached()` cancels, so shutdown ends them in seconds and their writes still land; the idempotent ones (`handleSetSchedule`, `handleUnpair`) stay on the request context. Their routes are registered as `s.tracked(s.requireAdmin(s.handleX))` (`handleDeleteCalendar`: `s.tracked(s.requireEveryday(...))`), so the `detached` counter is incremented the moment `ServeHTTP` dispatches -- before `requireAdmin`'s session lookup, which is itself a store round-trip that `ReadTimeout` (15s) lets outlast `shutdownTimeout` (5s). Registering inside the handler was too late: `Shutdown` returns after its timeout with requests still active, and one still in the auth lookup would leave `WaitDetached()` reading zero and the store closing under a request about to pin a key. The header-read window before `ServeHTTP` is entered cannot be covered by any counter, because no handler goroutine exists yet; `Shutdown`'s own drain is what covers it. The counter is a mutex and a `sync.Cond`, not a `sync.WaitGroup`, which panics when an `Add` from zero races an in-progress `Wait` -- two admin requests at SIGTERM do exactly that. `WaitDetached()` is what `cmd/server` blocks on before closing the store, because `http.Server.Shutdown` returns without knowing these goroutines exist.
- Audit actions: `backup.paired`, `backup.pair_failed`, `admin.backup_run` (details start with `outcome="success|failure"`), `admin.backup_unpair`, `admin.backup_key_pin`, `admin.backup_schedule`, `admin.backup_export` (a downloaded capsule, resource the capsule ID). `AuditDetails` flattens the lib's details map into the bounded audit field with locally derived fields first and remote error text last; values are quoted and `=` is escaped before the final `AuditSafe` cut. `cmd/server` uses it for the scheduler and CLI rows. - Rate-limit keys for `login:` and `password-change:` come from `limitIP` (`auth.ClientIP`, IPv6 cut to its /64), never from `RemoteAddr` or a raw header, so a limit is neither shared by everyone behind a proxy nor bypassable by forging `X-Forwarded-For` or rotating addresses in one /64. Per-account windows (`allowAccountAttempt`, login and password change) live in a separate map keyed by real user IDs (login adds the client's /64), so a flood of address keys in the per-IP map can never evict them; past `attemptsCap` a new key drops that map's expired windows, never a live one.
- Office networks (`exempt_networks.go`): `KY_RATE_LIMIT_EXEMPT_NETWORKS` plus the `rate_limit_exempt_networks` setting, parsed together by `ky-primitives/netallow` into `s.exempt` (an atomic pointer swapped on save). `officeExempt` matches the `requestIP` result only, never a raw header, and lets a listed request skip one per-IP limit only while that limit's shared office budget lasts (`officeBudget`, 300 a minute across all listed networks, kept in the never-evicting `accounts` map as `office:<bucket>`); past it the ordinary per-IP limit applies again, and only a request that actually skipped it is counted as exempted. 300 a minute for DAV's 15-minute window is 4 500 keys, under `attemptsCap` and `davFailKeysCap`, so office churn cannot evict live counters; a bigger budget or a longer window must keep that true. `allowPerIP` wraps `login:<ip>` and `password-change:<ip>`. DAV and `/mcp` share one budget (`dav-fail`, failures only: handed back on success) through `reserveDAVFailure`: an office request's `ip:`/`mcp-ip:` failure key gains `|<first 32 hex of SHA-256 of the lowercased Basic-auth name or the presented token ID>` (never caller text), so an exempt address keeps a 10-failure bound per account or token. Every DAV and `/mcp` request reserves that failure before the token lookup and releases it once the secret is right (or the per-user window is shut for a right secret), so concurrent guesses cannot outrun the 10; sign-in already reserves its per-account window before `passwordVerify`. Per-account windows (`login:<user>@<ip>`, `password-change:<user>`, `user:`, `mcp-user:`), the CAPTCHA, the unknown-token audit budget and every per-user limit (`freebusy:`, `itip:`, `feed:`, invitations, imports) never consult it; a new per-IP limiter must. A stored list that fails to load or parse at startup is dropped (logged) for the environment's, never widened. `exempt_networks_test.go` pins each of these.
- Login: 20 per `limitIP` per minute (429 after), and 10 failures per account and `limitIP` per 15 minutes (counted before the password check and refunded through `takeAccountAttempt`'s refund on a correct password, so concurrent guesses cannot all pass). An exhausted account window answers the same 401 `Invalid credentials`, after a dummy derivation, so it reveals no account, and keying it on the address keeps a stranger from locking someone else out. Every failure, unknown user, account without a password, wrong password, and disabled account with the right password alike, is the same 401 `Invalid credentials` and costs one Argon2 derivation (`password.DummyVerify` when there is no hash to check); status is checked only after a correct password. A PoW solution is spent on use (`powSpender`: `s.powSpent` on SQLite, `SpendChallenge` on PostgreSQL); a replay is 403.

- CSRF (`csrfValid`, before the mux): login (`credentialRoute`, exact path) needs, from a browser (`Origin` or `Sec-Fetch-Site` present), the token of the `ky_presession` cookie or of the session cookie (`ValidatePreSessionCSRF`); a client sending neither header needs none. `/api/sso/kysignon/sync` is exempt (signed: in multi-tenant mode `handleTenantDirectory` verifies KyIdentity's `syncauth` SCIM bodies, takes access away whatever the body's `org_id`, and changes a profile or erases only with the account's own org). Every other unsafe request with a session cookie needs that session's token (`ValidateCSRF`). - POST `/api/sso/kysignon/backchannel-logout` (`handleBackchannelLogout`, `requireSSO`) is the OpenID Connect Back-Channel Logout receiver for the live provider, either kind: anonymous, the signed token is its authority, and a request without a session cookie needs no CSRF token. Form field `logout_token`, body capped at 16 KiB, `Cache-Control: no-store`. No live provider is 404; any token failure is 400 `invalid_request`; an unusable provider (discovery, credential file) is 502, logged. Sessions store the sid as `ssoSID` (`<Binding> <sid>`), so a logout only ever names a login of the live provider. A `sid` ends every session of that login (`EndSSOSession`) and fences it for 10 minutes (`ssoLogoutFence`, past the 5-minute login cookies), so a callback still in flight answers 401 and sets no cookie. A token with only `sub` calls `EndSSOSubject(p.Binding, sub, iat + 1 s, …)`: it ends the sessions, dated before that cutoff, of every non-local account of that binding with that subject (so the `scim` row a KyIdentity login adopted too, and no row of another binding), and fences the cutoff for 10 minutes by binding and subject, not by account, so a callback in flight answers 401 even for a first login still provisioning. An unknown subject is 200 and fenced. A replay is 200. Each accepted logout audits `auth.sso_backchannel_logout`.
