# internal/calendar

## Purpose
Pure iCalendar rules: what a calendar object must contain and how it is indexed; sync token format.

## Local Contracts
- No I/O. Callers pass decoded `*ical.Calendar`.
- VEVENT or VTODO (VTIMEZONE beside them); one type and one UID per object; `Object.Component` names the type. Every VEVENT needs DTSTART. RRULE or RDATE on a component nested inside one (e.g. VALARM, which repeats with REPEAT/DURATION) is `ErrInvalidData`. Any other component is `ErrUnsupportedComponent`.
- A VTODO indexes DTSTART to DUE or DTSTART+DURATION, else DUE alone (`taskSpan`), one second wider at the start (the span is inclusive; the store tests `first_start < end`), with the same zone slack and recurrence rules as events (a DUE-only rule runs from DUE). A task with neither DTSTART nor DUE is indexed unbounded (`FirstStart` = `math.MinInt64`, `LastEnd` nil), so every range finds it; RRULE or RDATE on one is `ErrInvalidData`.
- `Components(names)` is the only component-set rule for MKCALENDAR and the API: empty is VEVENT; VEVENT, VTODO or both in that order; any other name is `ErrUnsupportedComponent`.
- `Recurring(cal)` reports RRULE or RDATE on any component outside VTIMEZONE, read from the decoded object (go-ical upper-cases names and unfolds lines), so `rrule:` or a name folded mid-line cannot hide one. Callers use it, never a byte search.
- `ResolveZone(tzid)` is the only TZID lookup for expansion and edits: tries IANA names via Go's data (the binary embeds `time/tzdata`), then Windows names through `windowsZones` (generated from CLDR release-48-2, territory 001, by `go generate`; the generator pins the source file's SHA-256), then old Thunderbird `/mozilla.org/<version>/<IANA>` paths. `loadIANA` helper refuses "" and "Local" at all lookup points. Unresolved zones are shown in UTC and flagged by callers.
- `FirstStart`/`LastEnd` are conservative: unknown or floating zones widen by 14h; rules past 100 years, or needing more than 100000 occurrences, index as unbounded (`LastEnd == nil`).
- Recurrence work is bounded by the rrule-go set iterator and one 100000-occurrence budget per object (VEVENTs and RDATE instances); RDATE is scanned locally (go-ical reads EXDATE instead). RRULEs are expanded by `ruleLast` with iteration cut at the 100-year horizon; a rule with neither COUNT nor UNTIL, or an unparseable rule or RDATE, indexes as unbounded. EXDATE is ignored (it only narrows).
- At most 10 RRULE-bearing VEVENTs per object are evaluated (the 11th and later index unbounded, no further expansion); FREQ=SECONDLY and FREQ=MINUTELY are never expanded (unbounded). RDATE parsing stops when the budget is spent (unbounded, FirstStart = epoch).
- A rule whose BYHOUR x BYMINUTE x BYSECOND exceeds 96 indexes unbounded without expansion: rrule-go builds every day of a period times that set before the first occurrence, so the budget cannot cap it.
- The budget counts `next()` calls, but rrule-go checks UNTIL only on a matching candidate, so one call on a rule that never yields scans to year 9999. `ruleLast` therefore runs the same feasibility guards as `Expand` (`ordinalsInRange`, `satisfiable`, `yields`, feasible.go) before iterating; a refused rule indexes unbounded. `yields` first checks `clockReachable`: an HOURLY/MINUTELY/SECONDLY step that can never land on its BYHOUR/BYMINUTE/BYSECOND clock (residues modulo gcd(step, 86400)) loops forever inside rrule-go. Rules that pass but never yield through interval aliasing with day filters (e.g. `DAILY;INTERVAL=7;BYDAY=TU` from a Wednesday) still scan to 9999 at day granularity, measured under 40 ms each.
- An RRULE on a component with an unknown or floating DTSTART zone, or more than one RRULE on a component, indexes unbounded without expansion.
- `LongParams(body)` reports a content line with a parameter value over `MaxParamValue` (1 KiB), reading lines and parameters exactly as go-ical's decoder does. go-ical builds parameter values a byte at a time, so decoding is quadratic in a value's length (900 KiB measured at 51 s); every decode of bytes from outside (CalDAV PUT, ICS feeds, inbound iTIP) runs it first. Linear.
- `CheckProps` bounds calendar name (255 bytes), description (4096 bytes) and colour (`#RRGGBB[AA]` or empty) for CalDAV and the JSON API alike.
- `Expand(cal, from, to, viewer, limit)` is the only recurrence expansion. go-ical is used to decode and encode only: its `RecurrenceSet` drops RDATE, fails on comma-separated EXDATE lists and on non-IANA TZIDs (2026-10-07 spike). Expansion iterates an `rrule-go` set that always includes the original DTSTART (RFC 5545), adds every RDATE and EXDATE value (lists and PERIOD starts), and replaces occurrences by RECURRENCE-ID overrides keyed by `occurrenceKey` in the first master's form (a date for all-day, wall-clock for floating, else the UTC instant). Overrides are placed by their own DTSTART, so one moved into the range appears and one moved out disappears; an override replaces a Partial master's DTSTART too. Floating times and dates use the viewer's zone; unresolved TZIDs parse as UTC and set `UnknownZone`. Bounds, in order:
  - One 100000-iteration budget is shared by every master of the object; a master that exhausts it before `to` drops its generated instances and yields only DTSTART with `Partial`, as do later masters. `ErrTooManyInstances` is only more than `limit` instances.
  - Masters past `maxRecurringComponents` (10) yield only DTSTART with `Partial`, as do the rules Inspect indexes as unbounded without expanding (several RRULEs, SECONDLY/MINUTELY, oversized time sets, unparseable rule or RDATE).
  - UNTIL is clamped to `to`; a date or floating UNTIL is read as wall time in DTSTART's zone (go-ical reads it as UTC); a UTC UNTIL on an all-day series is read by its UTC date, at 00:00 in DTSTART's zone.
  - A COUNT over 100000, or whose estimated periods from DTSTART to `to` exceed the budget, is Partial.
  - A COUNT-less DAILY/WEEKLY/HOURLY rule has its DTSTART advanced in wall time by whole intervals to just before `from` minus the event's length (all-day: its days), so an occurrence still running at `from` is kept. If that wall time does not exist in DTSTART's zone (a DST gap), one fewer interval is tried, at most twice, then DTSTART is kept. Estimates and skip-ahead divide before multiplying, so a huge INTERVAL cannot overflow.
  - rrule-go checks UNTIL only on a matching candidate, so never-matching rules are refused before iterating (Partial): `satisfiable` (feasible.go) checks BYMONTH/BYMONTHDAY/BYYEARDAY over a leap and a non-leap year template, ignoring BYDAY; a BYDAY ordinal beyond 5 (MONTHLY or BYMONTH) or 53 is Partial; `yields` probes rules with BYSETPOS, BYWEEKNO, or an ordinal BYDAY with BYMONTHDAY/BYYEARDAY with rrule-go itself, ending at its year-9999 cap and starting 400 years before (YEARLY/MONTHLY/WEEKLY), 40 (DAILY) or 8 (HOURLY); no occurrence is Partial.
- `testdata/recurrence/` holds hand-written fixtures in Apple, Google, Outlook and Thunderbird export styles (CRLF). Recorded real exports are Plan 4's interop gate.
- Web edits are pure functions over the decoded object that mutate in place, so unknown properties, X- properties, ATTENDEEs and VALARMs survive: `NewEvent`, `EditAll`, `EditOne` (writes or edits a RECURRENCE-ID override deep-copied from the master without RRULE/RDATE/EXDATE), `DeleteOne` (EXDATE plus removal of that occurrence's override; existing EXDATEs are compared as occurrence keys in the master's form, so repeating it, or an EXDATE written in UTC on a TZID master, adds no second EXDATE). Each edit sets DTSTAMP and LAST-MODIFIED and bumps SEQUENCE (capped at MaxInt32). `EditAll` compares the start in the master's own form (date, floating wall clock, or instant) and drops overrides, EXDATE and RDATE only when the start, all-day flag or repeat preset (weekday order ignored) changes; otherwise DTSTART stays as stored, an end change is written in DTSTART's form, and no VTIMEZONE is added.
- `EditText(cal, recurrenceID, TextEdit)` changes only SUMMARY, LOCATION and DESCRIPTION (nil keeps, empty removes) on the master (`""`) or on one occurrence's override, created by `EditOne`'s copy rule (`overrideOf`); times, the rule, EXDATEs and other overrides stay. `TextOf` reads that text (the override, else the master). The MCP `update_event` uses both so a field an agent leaves out is kept.
- Occurrences are named in the master DTSTART's form: a DATE, wall time in the TZID exactly as written (UTC wall digits for an unresolvable TZID, as `Expand` reads it), or UTC, and edits find overrides with the same `overrideKey` rule as `Expand`. `EditOne`/`DeleteOne` refuse (`ErrNoSuchOccurrence`) a key in another form than the master's, and a key that is neither an existing override nor an instance `Expand` yields within a day of it. Timed web events are written with `TZID=<IANA>` plus a generated VTIMEZONE (`VTimezone`: the offset in force at the start's year, then every real offset or DST change for 11 years; it steps past Go's stalled `ZoneBounds` in extrapolated years beyond tzdata's explicit transitions, drops boundaries that change nothing, and caps the list at `maxObservances`); UTC-anchored events use `Z` values. Repeat presets are `FREQ=DAILY|WEEKLY[;BYDAY=...]|MONTHLY|YEARLY`; anything else (`COUNT`, `UNTIL`, `INTERVAL` other than 1, ordinal `BYDAY`, other BY parts, RDATE) is `custom` and kept.
- `BusyTimes(cal, from, to, loc, limit)` is free/busy over `Expand`, by RFC 4791 §7.10: an instance (override or generated) with `TRANSP:TRANSPARENT` or `STATUS:CANCELLED` is free, `STATUS:TENTATIVE` is tentative, anything else busy. It returns times only, never text.
- `SeriesTimes(master, viewer)` returns the master's own first start, end and all-day flag, the values `EditAll` compares against.
- Sync tokens (and CTags) are `urn:kycalendar:sync:<epoch>:<calendar-id>:<seq>`: the calendar ID binds a token to one calendar, so one deleted and recreated at the same path (its seq restarts at 0) never accepts the old token. Tokens of any other shape are malformed.
